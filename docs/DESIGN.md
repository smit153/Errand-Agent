# Errand Agent — Design v2

**Design v3 · 7 November 2026 · stages 1–4 built, stage 5 in progress.** The assignment PDF is authoritative; no requirement or fixed tool contract changes. v3 (user decision) replaces local Ollama with the user's ModelMux gateway; see DECISIONS §17. [DECISIONS.md](DECISIONS.md) records details, superseded decisions, tests and build plan.

**Architecture and ownership.** Thin CLI (chat and trace side by side) → local FastAPI → explicit workflow → ToolClient/in-process mocks. One language agent calls the user's ModelMux gateway (local OpenAI-compatible Chat Completions; Claude Code or Codex, configurable) with `tools`/`tool_calls`. ModelMux runs locally; its models run on the providers' servers. PostgreSQL 16 + pgvector holds state, approvals, operations/attempts, provider state, memories/vectors, jobs, outbox and traces. Stateless workers resume durable jobs. Code owns IDs, dates, ranking, prices, slots, authorization, execution and consequential messages; the model extracts language and proposes restricted actions. No real errand providers/payments, Redis, Kafka, Kubernetes or separate vector database.

**State and guardrails.** `collecting → comparing → held → awaiting_approval → executing → verifying → completed`, plus conflict/retry/recovery states. Preserve unrelated facts on corrections. G1–G11 enforce state-scoped tools, real-value enums, code-resolved dates, deterministic ranking/templates, grounding checks, approved-snapshot dispatch, focused calls, degraded menus, bounded output repair and untrusted-data isolation. Local repair then at most three model retries; invalid actions never execute. Grounding violations regenerate once, then use templates. Trace all attempts. Model failure offers a visible deterministic menu without bypassing approval or reconciliation.

**Approval and recovery.** Code displays immutable action/provider/slot/price/hold-or-booking/expiry revisions. `confirm <token>` and plain `yes` must reference the latest actually displayed, unchanged revision. Expiry/material changes get specific explanations and fresh approval. Model proposes consequential tools; code rejects mismatches and dispatches only the exact approved snapshot. Stable operation key, separate attempt IDs, atomic approval consumption and unique proposal→operation prevent duplicates. Booking timeout forces authoritative status lookup before retry/success. Short transactions use per-session advisory locks, revision checks and durable fenced claims; none spans model/tool work. Backend effects and replay records commit together. Jobs use `FOR UPDATE SKIP LOCKED`; cancellation 503 retains its key, attempts and retry schedule across restarts. Outbox notifications have stable IDs and at-least-once delivery.

**Memory and limits.** Code creates unconfirmed inferred candidates; only user confirmation promotes them. SQL hard-filters eligible facts before embedding cosine ranking (local Ollama `nomic-embed-text`, embeddings only; DECISIONS §18); facts and 768-dimensional vectors share a row and transaction. Offline scenarios use fixture vectors; a real local embedder integration test checks ranking. Seed 50+ memories and a long prior conversation specifically to prove history never reaches model context. “Same electrician” uses `list_bookings`. The fixed input cap is 4,096 UTF-8 bytes of app-assembled messages and tool schemas, which bounds app tokens without a tokenizer; ModelMux's own prompt overhead is traced, not counted (DECISIONS §18); drop reviews, low-ranked memories, extra candidate detail, then retry excerpts. The counted clarified booking uses nine focused calls, ten with history; retain per-run caps of ten logical/forty physical calls, twenty tool calls and 300 active seconds, plus durable operation lifetime caps.

**Evidence.** Postgres traces export JSONL: transitions, context, attempts, tools, sanitized results, latency, usage and costs where available.
